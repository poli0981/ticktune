# v2.0 live checklist

Same two halves as v1.1 (`docs/14 §5`):

1. **Before the tag**, on the `docs/sync-2.0` PR's **preview version** — the
   last PR, so its preview is `main` as it will ship. It runs the real Worker,
   `_headers`, the CSP and the `YT_DATA_API_KEY` secret, and it is a fresh
   origin, so the first visit is a first run.
2. **After the signed tag**, a short re-check of production itself.

Desktop browser. Chromium first; the lines marked 🦊 / 🧭 also in Firefox /
Safari.

## Before anything — the deploy model

- [ ] **Pushing a branch did not deploy it.** `pnpm wrangler deployments list`
      shows no new deployment after the push; `versions list` shows a new
      version.

## Blocking — on the preview version

### Legal 2.0

- [ ] **A returning user is asked once.** In a profile that accepted 1.1, the
      gate appears again, names the YouTube Data API in its YouTube line, and
      does not appear after Accept + reload.
- [ ] **All eight legal pages read `Version 2.0 · 2026-10-21`**, VI and EN; the
      EULA has §8 Governing law (Viet Nam) and §9 Contact.

### YouTube lengths (Data API)

- [ ] **Three links in one paste** → each row shows a length within a few
      seconds, the queue footer shows the total, and "Match queue length" is
      enabled. DevTools → Network: one `/api/yt/durations?ids=…` for the batch.
- [ ] **A private or deleted link** gets no length and no error toast beyond
      the existing cause line.
- [ ] **One video playing for a minute, Console clean.** v2.0 dropped
      `img-src https://i.ytimg.com` after measuring the app never uses it; the
      measurement could not cover playback, because YouTube refuses an
      automated browser (`tests/manual/yt-matrix.md`). A CSP violation here
      means the origin goes back before the tag.

### Offline (PWA) 🦊

- [ ] **The browser offers to install** `/app/` (Chromium: the install icon in
      the address bar). Installed, it opens on `/app/` in its own window.
- [ ] **Offline start.** Load `/app/` once, then DevTools → Network → Offline
      (or unplug): reload → the app starts, a local file imports and plays,
      the countdown runs. YouTube mode says it needs a connection.
- [ ] **Only `/app/` is controlled** — DevTools → Application → Service
      workers: scope `/app/`; the landing and legal pages are plain pages.
- [ ] 🦊 **Offline start in a real Firefox.** CI cannot cover it: Playwright's
      Firefox offline mode refuses the navigation before the worker answers
      (`NS_ERROR_OFFLINE`). Network off for real, then reload `/app/`.

### Settings file

- [ ] **Export** saves `ticktune-settings-YYYYMMDD.json`; **Import** into a
      fresh profile applies it (theme, face, volume…) without skipping the gate.

### Themes and faces 🦊 🧭

- [ ] **Light (LCD)** reaches every app screen — Setup, player in all three
      modes, Settings, Finished, the info modal — and the landing stays dark.
- [ ] **DSEG14** in the countdown and its ghost, every format, same width.
- [ ] 🔴 **The YouTube player is never covered** — light theme + DSEG14, a
      2-hour countdown, window at 1280 and 1024 wide: open Settings, the info
      modal, let the bottom bar appear.

### Japanese 🧭

- [ ] **`/ja/`** renders with no missing glyphs; its 404 is Japanese; the
      language links in the nav reach `/`, `/en/`, `/ja/`.
- [ ] **The app in 日本語** from the header's third key: Setup, player,
      Settings, Finished; legal links open the English texts.
- [ ] **JSON-LD**: view source on `/`, `/en/`, `/ja/` → one
      `application/ld+json` block that parses.

### Finish notification 🦊

- [ ] **Turning it on asks once, in the click**; refused → the switch stays off
      with the reason.
- [ ] **Hidden tab**: a 1-minute countdown, switch to another tab → one
      notification at zero, generic text ("Time is up"), never a track name.
      Clicking it brings the tab back. Coming back by hand closes it.
- [ ] **Visible tab**: no notification.
- [ ] 🧭 **Safari** (if a Mac is at hand): the page shows it instead of the
      worker — best-effort, may be late.

### Crossfade (S4b passed; shipped in #92) 🦊

- [ ] **Listen to ten playlist transitions** at the default 2 s, on speakers,
      with real music: no gap, no click, no level dip, no truncated ending.
- [ ] **⏭ in the middle of a crossfade** loads the next track cleanly — and a
      plain ⏭ outside one no longer clicks (it ramps).
- [ ] 🦊 **Pause in the middle of a crossfade** and resume — no click (Firefox
      has no `cancelAndHoldAtTime`), and the fade carries on where it was.
- [ ] **Single mode, loop style "Chuyển mềm"**: the track fades into itself
      and Loop ×N counts each pass.
- [ ] **Settings → Âm thanh → 0 s**: transitions become straight cuts at the
      end of each track, with no audible gap.
- [ ] **A fresh profile**: nothing plays before the first gesture.
